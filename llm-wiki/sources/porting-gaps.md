> 원본 문서는 2026-10-02 에 저장소에서 삭제했다(위 `git show` 로 읽는다). 이 요약은 삭제 시점의 문서가 주장한 바이며 현재 코드와 다를 수 있다.

## 요약

레거시 AvantFAX(PHP) 소스를 한 줄씩 대조해 NamiFAX(Python)에서 미구현되거나 오동작하는 항목을 전수 조사한 보고서. 사용자 화면(11개 고장), 보안(5개), 관리자 화면(10개), 부가 기능(3개), 명령줄·훅·설정(11개), 설치·운영(2개), 레거시와 재대조 결과(8개 실제 차이) 등 총 50+개 항목을 체계적으로 식별 및 기록. 각 항목마다 근거 코드 경로, 영향도, 정정 방법을 명시하고 권장 우선순위 4단계를 제시.

## 핵심 내용

**A. 화면에 있는데 고장 난 것 (사용자 직면)**
- A1: `send_mail` 첨부, CC/BCC, 썸네일 첨부 불가 (팩스 메일 보내기 전혀 작동 안 함)
- A2: 받은 팩스함이 처음 25건만 표시, 페이지 나누기·쪽 이동 없음
- A3: 받은 팩스함 행의 "보관"·"삭제" 버튼이 라우트 없음(404), 선택 삭제 권한 검사 없음
- A4: 팩스 보기가 실제 페이지 이미지 모형, 이전/다음·메모·버튼 없음, 썸네일도 공백
- A5: 검색이 카테고리·필터·쪽 나누기·열·행 동작 없음, OpenSearch 미구현
- A6: 주소록 편집에서 팩스 번호 `required`라 번호 없이 저장 불가
- A7: "업체 지정" 모달이 `abook_id=1` 고정, 업체 이름 바꾸기 코드 오류
- A8: 팩스 발신자 링크 검색이 적용되지 않음(`q` 파라미터명 불일치)
- A9: 팩스 메일 보내기 시 파일을 못 불러와도 첨부 없이 전송, CC/BCC·분류·서명 없음
- A10: 환경설정이 표지·쪽당 개수 저장하지 않음
- A11: 연락처·배포 그룹 선택, 표지 접기, 다중 파일 목록, 표지 자동 채우기 등 부분 처리

**B. 보안 (Critical/High)**
- B1: `/ajax/deletefaxes` 반사형 XSS(fids 이스케이프 없음)
- B2: 관리자 사용자 생성 시 비밀번호 빈칸 → 평문 "password", 강제 변경 메일 없음
- B3: 상태 변경 POST에 CSRF 토큰 없음(원본도 없으나 `SameSite=Lax` 의존)
- B4: `/ajax/modemstatus`가 모든 모뎀 상태 반환(권한 검사 없음)
- B5: 로그인 성공·실패 감사 로그 없음

**C. 관리자 화면**
- C1: 사용자 편집에서 회선·DID·카테고리 배정 미저장, 계정 활성·비밀번호 주기 필드 없음
- C2: `any_modem` 체크 해제해도 항상 1로 저장
- C3: 사용자 저장 오류 조용히 삼킴, 메시지 없음
- C4: 대시보드 HylaFAX 버전 고정 "6.0.7", 모뎀 상태 색 없음
- C5: 모뎀 편집에서 삭제 버튼 없음, 장치명 중복 시 오류 대신 조용히 수정
- C6: 카테고리 삭제해도 기존 팩스의 `faxcatid` NULL로 안 바뀜(고아 레코드)
- C7: 시스템 재부팅·종료 버튼이 메시지만, 백업은 매니페스트만(실제 아카이브·DB 덤프 없음)
- C8: 시스템 로그가 100행에서 조용히 잘림
- C9: 메뉴·필드 숨기기 설정(`ENABLE_DID_ROUTING` 등) 동작 없음

**D. 사용자 부가 기능**
- 새 팩스 알림(배지, 30초 폴링, 소리, 모뎀 상태 폴링 중 일부만 처리)
- 주소록 실시간 필터, 이메일/팩스 이동, 연락처·배포 그룹 선택 등 부분 처리
- 전송 보고서에 팩스 번호·이미지·상태 표시 없음

**E. 명령줄·훅·변환·설정**
- E1: 수신 팩스 자동 인쇄(`PRINTFAXRCVD` 등) 없음
- E2: `notify`의 `loadbyfaxnum` 결과 분기 오류로 새 수신자 번호 미생성, 회사ID 비움
- E3: `faxinfo`가 TIFF 아닌 파일에 가짜 값 반환해 손상 파일 검사 무력화
- E4: PS/PDF 변환·합치기 등 처리됨(일부 처리됨 표시)
- E5: HTML 표지·NUM_PAGES_FOLLOW 없음, PostScript 이스케이프 없음
- E6: 설정 기본값이 원본과 반대(`ARCHIVEFAX2EMAIL` 등), 날짜 형식 불일치
- E7: 약 70개 설정 변수 미구현(경로, OCR/바코드, 메일 인코딩, 썸네일 크기 등)
- E8: 훅 시스템 로그, 스키마 마이그레이션 최적화 등
- E9: 파일 업로드 검사 클래스 미사용
- E10: 기본 표지 파일명 불일치(`standard.ps` vs `cover.ps`), 카테고리 미존재
- E11: 2.x 이전 DB `update_contacts` 지원 안 함

**F. 설치·운영**
- 훅 스크립트·설정 조각·sudoers·cron·웹 서버 설정 문서 불완전
- 이메일-팩스 게이트웨이 미구현
- HylaFAX 사용자 동기화(`faxadduser`/`faxdeluser`) 없음

**G. 레거시와 재대조 결과 (코드 직접 비교)**
- 웹 진입점 74개(`.php` 36, `ajax/` 13, `admin/` 25) ↔ 라우트: 이름으로 대응 완전 확인
- DB 테이블 14개: 컬럼 모두 존재, 이식본의 새 테이블 6개(신규 기능용)
- 명령줄·훅 14개: `update_contacts`(2.x 이전 DB용, 미지원)를 뺀 13개 대응
- 설정 변수 147개: 약 70개 미구현(대체됨), G1~G8이 실제 차이
- 화면 문구 332개: 144개 미일치(표현 다름), 주요 동작 문구는 누락 없음

**G1~G8 실제 차이(모두 처리됨)**
- G1: "White Pages에서 찾기" 링크 없음
- G2: 새 팩스 윈도우 포커스·알림·소리 스위치(`FOCUS_ON_NEW_FAX` 등) 기본값 다름
- G3: 보관함 마우스 올리기 미리보기 동작 없음
- G4: 수신함 한 쪽 기본 건수 10(이식본) vs 25(원본), 기존 저장값 유지(추측 불가)
- G5: 수신함 새 팩스 와도 목록 새로고침 안 됨(배지만 갱신)
- G6: TIFF→PDF 대체 경로가 RGB로 바꾸고 해상도 버려 파일 6배 증가·인쇄 크기 오류
- G7: HTML 엔티티 저장된 이름(`M&uuml;ller`) 표시 오류, 읽을 때만 풀어서 표시로 처리
- G8: 영어 화면 문구 26개를 원본 원문으로 맞추고 번역 채우기로 처리(언어당 35% → 42~47%)

**변환 도구 변수 대조**
- `TIFFCP`, `CONVERT`, `GSCMD` 등 17개 변수 대부분 구현 또는 대체
- `TIFF_TO_G4`, `HYLATIFF2PS`, `GSN` 등 일부는 쓰이지 않는 죽은 변수

**JavaScript 대조**
- 12개 파일(업체·연락처 필터, 모뎀 상태, 다중 파일, 수신 대기, 행 미리보기, 쪽 넘김, 팝업 대화상자 등) 대부분 구현
- 페이지형 대화상자는 의도한 차이(원본의 모달 ↔ 이식본의 별도 페이지)

## 문서가 주장하는 수치·상태

- 총 조사 항목: 50+ 개 (A 11개 + B 5개 + C 10개 + D 3개 + E 11개 + F 2개 + 기타 8개)
- 완료 표시: ✅ 모두 표시(각 항목마다 처리 완료)
- 전수 대조 범위:
  - 웹 진입점: 74개 확인(빠진 것 없음)
  - DB 테이블: 14개(32+32 컬럼 완전 대응)
  - 명령줄·훅: 13개(1개 미지원)
  - 설정 변수: 147개(약 70개 미구현)
  - 화면 문구: 332개(144개 미일치는 표현 차이)
- 실제 차이(G1~G8): 8개 항목 전부 처리됨
- 제외 사항: SAML/패스키/TOTP(신규 기능), 한국어 외 번역 보류, 페이지형 대화상자(의도 선택), 레거시 CSS(Tailwind 대체)

## 낡았을 가능성이 큰 부분

- 문서 작성 일자(2026-10-02)가 가장 최근 개발 스냅샷이지만, A/B/C/D/E 섹션의 많은 항목들이 "완료(✅)" 표시로 되어 있어 실제 현재 코드 상태와의 괴리가 있을 수 있음
- G1~G8의 "처리됨" 주장이 실제 코드에서 여전히 존재할 수 있음(예: A5의 OpenSearch, A2의 페이지 나누기, A4의 팩스 이미지)
- E7의 약 70개 설정 변수 "미구현" 상태 중 일부는 이미 구현되었을 수 있음(예: `BINARYDIR`, `CALLIDn_*`, `RESTRICTED_USER_MODE` 등)
- "제외(이미 결정했거나 대체됨)" 섹션이 의도한 차이(신규 기능, Tailwind CSS)와 실제 이식 한계를 구분하지 않을 수 있음

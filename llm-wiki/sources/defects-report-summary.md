## 요약

당시 조사(2026-10-01 보고)에서는 NamiFAX 레포지토리(numfax, HEAD `e3e50c8`)에 대해 5라운드 반복 조사를 수행하여 총 490건의 결함을 보고했습니다(1라운드 121건, 2라운드 105건, 3라운드 192건, 4라운드 34건, 5라운드 38건). 조사 초기 발견 K01~K16(16건)을 별도로 기록했습니다. 조사는 배포 코드 기준이며 저장소 소스를 수정하지 않았습니다. 심각도 기준으로는 수렴에 가까우나(최근 2라운드 신규 결함 72건 중 치명 1건, 높음 6건), 건수 기준으로는 수렴하지 않았습니다.

## 결함 분류

### 치명 등급 (9건)

- **ADM-01**: 앱 시작마다 seed/migration이 운영 데이터 덮어쓰기
- **COR-01**: SQLite 단일 연결을 스레드 공유 → 세그폴트
- **COR-02**: 기동마다 seed/migration이 실제 데이터 변조
- **COR-03**: notify CLI가 모든 사용자에 대해 AttributeError로 종료
- **COR-04**: send_mail이 실제 발송 없이 성공 반환
- **SEC-01**: 비인증 SQL 인젝션 (주소록 검색, UNION 기반 데이터 탈취)
- **USR-04**: 사용자별 모뎀 접근 제한 완전 비동작
- **USR-06**: `/ajax/faxalter`에서 쉘 명령 주입 가능
- **R4U-01**: 관리자(uid=1) 삭제 보호를 문자열 우회로 가능

### 높음 등급 (113건)

높음 등급은 영역별로 분류:
- **관리자 화면(ADM)**: 사용자/모뎀/DID/커버/카테고리 CRUD 실패, 동적 설정 테이블 불일치, Cover Studio 템플릿 주입, SMTP/스토리지 설정 미저장 등 (15건)
- **코어/DB(COR)**: 메서드/테이블/컬럼 존재 불일치, 스키마 불일치(PK 이름), 데이터베이스 연결 누락, 쿼리 예외 은폐, 주소록 검색 SQL 인젝션, 배포 시 avantfax 미포함 등 (33건)
- **보안**: IDOR, 반사 XSS, 비밀번호 만료 미강제, 해시 약함(무솔트 MD5), TOTP 평문 저장 등 (9건)
- **사용자 권한**: 2FA 미강제, 비밀번호 변경 경로 전무, can_del/modem/category 권한 미검사, 로그아웃 상태 주소록 조회 가능, 송신 큐 노출, 아카이브 검색 미동작, 발송 권한 미적용 등 (26건)
- **UI/렌더링**: 설정 저장 안 됨, 메시지 출력 안 됨, 버튼 무동작, 번역 문자열 부재, CSS 클래스 누락, 가짜 데이터 표시 등 (6건)
- **수신/발송**: 작업 취소 미동작, 재전송 스텁, 업로드 검증 부재, 업로드 임시파일 미삭제, 모뎀/카테고리 권한 무시, 발신자 정보 미전달, 아카이브 조회 실패 등 (18건)

### 중간 등급 (210건)

- 스토리지 정책 미적용, 경로 탈출 가능
- 테스트 체계 결함(mock 남용, 골든 마스터 자기 참조)
- CLI 기본값 위험, 진입점 인자 무시
- 환경변수 불일치, 패키징 이중 트리
- PHP 브리지 미사용/불안전, 설정 저장 검증 부족 등

### 낮음 등급 (158건)

- 로그 기능 미실행, 파일 권한 오류 무시
- 의존성 선언 불일치, 버전 고정
- 필드 누락/검증 부재, 오류 메시지 미포장

## 보고서가 주장하는 수치

- **총 결함**: 490건 (K01~K16 별도 16건)
- **라운드별 분포**
  - 1라운드(영역별): 121건 (치명 8, 높음 39, 중간 56, 낮음 18)
  - 2라운드(업무 흐름별): 105건 (높음 47, 중간 39, 낮음 19)
  - 3라운드(파일 정독): 192건 (높음 21, 중간 83, 낮음 88)
  - 4라운드(마스킹/퍼징/E2E): 34건 (치명 1, 높음 3, 중간 16, 낮음 14)
  - 5라운드(재검증/레거시 대조): 38건 (높음 3, 중간 16, 낮음 19)
- **심각도별**: 치명 9, 높음 113, 중간 210, 낮음 158
- **조사 방법**: 5라운드 반복, 최종 라운드에서 건수는 여전하나 심각도 수렴 판단으로 종료

## 한계·시험하지 못한 것

당시 조사가 스스로 밝힌 미검증 항목:
- Cover Studio, OCR, 실제 HylaFAX, 실제 IdP(SAML), 실제 S3/GCS와의 연동은 실환경에서 검증 불가
- CLI 동시성 시험(요청 번갈아 보내기) 미실행
- `cli/notify.py` 실행 후 `ArchiveOut` 기록 미확인
- 레거시 admin `conf_*` 편집 화면과 `upload_*`의 완전 대조 불가
- PHP 브리지 결함은 Python 호출 모사로 재현(PHP 환경 부재)
- `namifax-server` 명령의 포트 미개방 현상 원인 미분석
- 문서의 테스트 통계("296/296", "374/374")와 실측(362 passed, 88 passed) 불일치

## 근본 원인 10가지

보고서가 제시한 주요 원인 카테고리(개별 결함 대부분이 이들 중 하나에 해당):

1. **C1**: 연결 없는 DB 엔진과 세션 미구성
2. **C2**: 존재하지 않는 메서드/테이블/컬럼 호출
3. **C3**: 스텁과 가짜 데이터 반환
4. **C4**: 실패를 성공으로 위장(예외 삼키기)
5. **C5**: 보안(SQL 인젝션, 명령 주입, IDOR, XSS, CSRF 부재, 평문 저장)
6. **C6**: 데이터 손실과 훼손(기동 시 덮어쓰기, 가짜 변환 결과로 원본 삭제)
7. **C7**: 레거시 패리티 갭(98개 대조 항목 중 2개만 완전, 60개 부분, 20개 스텁, 16개 누락)
8. **C8**: 검증 체계 결함(mock 의존, 골든 마스터 자기 참조)
9. **C9**: 배포와 패키징(wheel 미포함, 폴백 앱, 기동 경로 개발 서버)
10. **C10**: UI/CSS/번역(CSS 69개 클래스 누락, 번역 68개 문자열 없음, JS 자동완성 미구현)

# 스토리지와 스케줄러

**스토리지 및 클라우드**(`/admin/storage`, *최고 관리자 전용*)에서는 저장소 종류와 보존 기간 정책을 정합니다. **예약 작업**(`/admin/scheduler`, *관리자 콘솔* 또는 *최고 관리자*)은 정리 작업을 돌리며, 보존 기간 정책을 적용하는 작업도 여기에 있습니다.

## 스토리지 및 클라우드

화면에는 양식이 두 개 있습니다.

### 보관 수명주기 정책

| 항목 | 의미 |
|---|---|
| **로컬 TIFF 삭제 시점 (일)** | 받은 팩스는 `fax.tif`와 `fax.pdf`로 보관됩니다. 이 일수보다 오래된 TIFF를 지우되, 같은 폴더에 내용이 있는 `fax.pdf`가 있는 경우에만 지웁니다. `0`은 즉시입니다. 범위는 0~3650이고 기본값은 7입니다. 나이는 파일 수정 시각 기준입니다. |
| **팩스 전체 보관 기간 (일)** | 보관 시각이 이 일수보다 오래된 팩스를 데이터베이스 기록, 파일, 원격 사본까지 모두 삭제합니다. `0`은 영구 보관입니다. 범위는 0~7300이고 기본값은 365입니다. |
| **팩스를 삭제할 때 클라우드의 객체도 함께 삭제** | 켜 두면(기본) 팩스를 지울 때 S3 버킷의 원격 사본도 지웁니다. 버킷에 연결할 수 없어도 로컬 팩스는 지워집니다. |

**수명주기 정책 저장**을 누릅니다(*수명주기 정책을 저장했습니다.*).

!!! warning "정책을 저장하면 자동 삭제가 켜집니다"
    입력 칸에는 기본값 7과 365가 보이지만, **정책을 한 번 저장하기 전에는 아무것도 지우지 않습니다.** 저장한 뒤에는 스케줄러의 *보존 기간 정책 적용* 작업(기본 켜짐, 매일 00:00)이 보존 일수를 넘긴 팩스를 삭제하고, **지금 실행**을 누르면 즉시 같은 일을 합니다. 삭제된 팩스는 NamiFAX에서 되살릴 수 없으므로 먼저 [백업을 내려받고](system.md) 일수를 신중하게 정하십시오. 팩스를 영구 보관해야 하면 보관 기간을 `0`으로 두십시오.

TIFF 삭제와 정리는 `NAMIFAX_ARCHIVE_DIR`(기본 `/var/spool/hylafax/archive`) 폴더에서 파일을 찾습니다. 팩스 보관함이 다른 곳(`AVANTFAX_ARCHIVE`)에 있다면 `NAMIFAX_ARCHIVE_DIR`도 같은 폴더로 맞추십시오.

### 클라우드 저장소

**저장소 종류**는 두 가지입니다.

- **로컬 파일 시스템 (기본)**: 팩스는 이 서버의 보관 폴더에 그대로 저장됩니다. 더 채울 항목은 없습니다.
- **Amazon S3 / MinIO / Ceph**: S3와 호환되는 모든 객체 저장소입니다.

S3를 고르면 다음을 채웁니다.

| 항목 | 의미 |
|---|---|
| **엔드포인트 URL (MinIO / S3 호환)** | Amazon S3는 비워 둡니다. MinIO나 Ceph는 그 주소를 입력합니다. 예: `http://minio.internal:9000`. |
| **리전** | 예: `us-east-1`. |
| **버킷 이름** | 사용할 버킷입니다. |
| **액세스 키 ID**, **시크릿 액세스 키** | 인증 정보입니다. 둘 중 하나라도 비어 있으면 AWS 라이브러리의 기본 인증 탐색(환경변수, 인스턴스 역할 등)을 씁니다. 저장할 때 시크릿을 비워 두면 저장된 값을 유지합니다. 시크릿은 암호화해서 저장하므로 `NAMIFAX_SECRET_KEY`(또는 `secret.key`)가 정해져 있어야 합니다. |
| **키 접두어** | 선택입니다. `faxes/` 같은 폴더 접두어입니다. |

- **저장소 설정 저장**은 설정을 저장합니다(*클라우드 저장소 설정을 저장했습니다.*).
- **연결 테스트**는 저장하지 않고 지금 양식에 있는 값으로 버킷에 연결할 수 있는지 확인해서 알려 줍니다. 시크릿을 비워 두면 저장된 값을 씁니다.

S3의 용도: 팩스를 **받으면** 수신 훅이 `fax.tif`와 `fax.pdf`를 버킷의 `<접두어>fax<id>/` 아래로 복사합니다. 실패해도 [시스템 로그](system.md)에 기록만 남고 수신은 계속됩니다. S3를 켜기 전에 받은 팩스는 나중에 올라가지 않습니다. 보존 기간 정책이 팩스를 지울 때는 원격 사본도 지웁니다.

## 예약 작업

스케줄러는 NamiFAX 웹 서비스 안에서 돕니다. 환경변수 `NAMIFAX_ENABLE_SCHEDULER`를 `1`/`true`가 아닌 값으로 두지 않은 한 서비스와 함께 시작합니다.

### 스케줄러 상태 상자

맨 위의 색 상자가 지금 상황을 알려 줍니다.

| 메시지 | 의미 |
|---|---|
| *스케줄러가 실행 중입니다 (마지막 확인 n 초 전)* | 최근 180초 안에 스케줄러 프로세스가 신호를 보냈습니다. |
| *스케줄러를 시작하는 중입니다…* / *…정지하는 중입니다…* | 변경을 적용하는 중이며 몇 초 걸립니다. |
| *스케줄러가 정지되어 있습니다* | 관리자가 정지했습니다. 아무 작업도 저절로 돌지 않지만 **지금 실행**은 계속 쓸 수 있습니다. |
| *실행 중인 스케줄러가 없습니다* | 신호를 보낸 프로세스가 없습니다. 웹 서비스를 `NAMIFAX_ENABLE_SCHEDULER=1`(기본값)로 시작하십시오. 그때까지는 **지금 실행**으로만 작업이 돕니다. |

상자 안의 버튼은 **스케줄러 정지** 또는 **스케줄러 시작**입니다. 정지는 데이터베이스에 기억되므로 웹 서비스를 다시 시작해도 유지됩니다.

### 네 가지 작업

작업마다 체크 상자(사용 여부), 설정, 상태 줄, **지금 실행** 버튼이 있습니다. 모든 설정은 맨 아래의 **저장** 버튼 하나로 함께 저장됩니다(*예약 작업을 저장했습니다. 실행 중인 스케줄러는 1분 안에 변경을 반영합니다.*). 시각은 24시간제 `HH:MM`으로 쓰며, 잘못된 시각은 메시지와 함께 거절되고 이전 시각이 유지됩니다.

| 작업(화면 이름) | 하는 일 | 기본값 | 설정 |
|---|---|---|---|
| **임시 폴더 정리** | 지정한 일수보다 오래된 임시 파일을 매일 지웁니다. | 켜짐, 00:00, 1일보다 오래된 것 | **시각 (HH:MM)**, **기준 일수(일)**(1~3650) |
| **오래된 팩스를 보관함으로 이동** | 받은 팩스함에서 지정한 일수보다 오래된 팩스를 보관함으로 옮깁니다. 삭제하지 않습니다. | **꺼짐**, 01:00, 30일보다 오래된 것 | **시각 (HH:MM)**, **기준 일수(일)**(1~3650) |
| **보존 기간 정책 적용** | 스토리지 화면에 저장한 TIFF 정리와 보존 기간을 적용합니다. 저장된 정책이 없으면 아무것도 지우지 않습니다. 상자에 저장된 정책(*TIFF n / 보존 n 일*)이 나옵니다. | 켜짐, 00:00 | **시각 (HH:MM)** |
| **주소록을 HylaFAX로 내보내기** | 주소록을 HylaFAX 전화번호부로 주기적으로 내보냅니다. | 켜짐, 60분마다 | **주기(분)**(1~10080) |

### 지금 실행, 중지, 상태

- **지금 실행**은 작업을 바로 백그라운드에서 시작합니다. 작업이 꺼져 있어도, 스케줄러가 정지되어 있어도 됩니다. 이미 돌고 있으면 *이 작업은 이미 실행 중입니다.*가 나옵니다.
- 작업이 도는 동안 그 줄에는 *실행 중 — 시작 …*과 **중지** 버튼이 나옵니다. 중지는 작업에 멈추라고 요청하며, 작업은 다음으로 안전하게 멈출 수 있는 지점에서 멈춥니다(그동안 *중지하는 중…*으로 표시됩니다).
- 작업이 끝나면 줄에 **마지막 실행** 시각과 요약이 나옵니다. 옮기거나 지운 팩스 수가 나오거나, 실패했다면 `failed: …`와 이유가 나옵니다. 한 번도 돌지 않았으면 *아직 실행된 적이 없습니다.*가 나옵니다. 실행마다 [시스템 로그](system.md)에도 기록됩니다.
- 작업이 도는 동안 상태 블록은 저절로 새로 고쳐집니다.

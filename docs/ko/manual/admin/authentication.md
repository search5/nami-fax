# 인증

이 페이지는 사람들이 로그인하는 방법을 관리자의 관점에서 설명합니다. 무엇을 설정하고, 사용자가 스스로 하는 일이 무엇이며, 로그인을 무엇이 지켜 주는지를 다룹니다. 관리 화면이 있는 것은 SAML뿐이고, 나머지는 환경변수와 사용자 설정으로 정합니다.

## 로그인 방법

| 방법 | 설정하는 곳 | 비고 |
|---|---|---|
| 사용자 이름과 비밀번호 | [사용자](users.md) | 항상 쓸 수 있습니다. [로그인 시도 제한](#throttle), 비밀번호 만료 규칙, 사용자가 켰다면 TOTP가 적용됩니다. |
| 패스키 | 사용자가 자기 설정에서 | 로그인 화면에 **패스키로 로그인 (Touch ID / 보안 키)** 버튼이 항상 있습니다. |
| SAML 2.0 SSO | 관리 화면 **SAML 2.0 SSO** | SAML을 사용하도록 켜고 IdP 로그인 URL을 입력했을 때만 로그인 화면에 **SAML 2.0 기업 SSO (Okta / Entra ID)** 버튼이 나옵니다. |
| 시스템 비밀번호(PAM, `pwauth`) | 환경변수 `ALTERNATE_AUTH_ENABLE`, `ALTERNATE_AUTH_CLASS`, `ALTERNATE_AUTH_FALLBACK`, `PWAUTHPATH` | 선택 사항입니다. 계정은 NamiFAX에도 있어야 합니다. `ALTERNATE_AUTH_FALLBACK`이 켜져 있으면(기본) 시스템 비밀번호가 틀렸을 때 NamiFAX 비밀번호를 쓸 수 있습니다. |
| 웹 서버 로그인 | 환경변수 `WEBSERVER_AUTH` | 선택 사항입니다. 웹 서버가 설정한 `REMOTE_USER`를 믿습니다. 기본은 꺼짐입니다. |

## SAML 2.0 SSO

**SAML 2.0 SSO**(`/admin/saml`, *최고 관리자 전용*)는 NamiFAX를 서비스 제공자(SP)로서 Okta, Microsoft Entra ID, Google Workspace, Keycloak 같은 인증 제공자(IdP)와 연결합니다.

### 설정 순서

1. 화면을 엽니다. **NamiFAX SP 접속 주소** 상자에서 **ACS(Assertion Consumer Service) URL**과 **SP 엔터티 ID / 메타데이터 URL**을 복사하고 **NameID 형식**(`urn:oasis:names:tc:SAML:1.1:nameid-format:emailAddress`)을 확인해 IdP에 입력합니다. **SP 메타데이터 XML 내려받기**를 누르면 같은 정보를 파일로 받습니다. 주소는 화면을 연 주소로 만들어지므로, 관리 화면을 NamiFAX의 공개 주소(예: `https://fax.example.com`)로 여십시오.
2. IdP에서 사용자의 이메일 주소를 NameID(또는 `email` 속성)로 내보내게 하고, 원하면 표시 이름을 `displayName`이나 `name`에 담습니다.
3. NamiFAX로 돌아와 **IdP(인증 제공자) 설정**을 채우고 **SAML 설정 저장**을 누릅니다.

| 항목 | 의미 |
|---|---|
| **SAML 2.0 싱글 사인온 사용** | 로그인 화면에 SSO 버튼을 보여 줍니다. |
| **IdP 엔터티 ID / 발급자** | IdP의 엔터티 ID입니다. 입력하면 모든 응답의 발급자가 이 값과 같아야 합니다. 비워 두면 발급자를 확인하지 않고 서버 로그에 경고만 남기므로 반드시 입력하십시오. |
| **IdP 싱글 사인온 서비스 URL (HTTP-Redirect / POST)** | 사용자를 로그인시키러 보낼 주소입니다. 없으면 SSO 버튼이 나오지 않습니다. |
| **IdP 공개 X.509 인증서 (PEM)** | IdP의 서명을 검증하는 인증서입니다. 없으면 모든 SAML 응답이 거절됩니다. |
| **JIT(첫 로그인 시) 계정 생성** | 켜면(기본) 처음 SSO로 로그인할 때 계정을 만듭니다. |
| **JIT 사용자의 기본 권한** | 화면에는 **Standard User** 또는 **Administrator**로 나옵니다(영어 그대로). *Administrator*를 고르면 새 계정에 *관리자 콘솔* 플래그가 붙습니다. IdP에서 권한을 가져오도록 설정하면(아래) 무시됩니다. |

저장할 때 입력값을 검사하지는 않습니다.

### SAML 로그인을 받아들이는 조건

- 응답은 설정한 인증서로 IdP가 **서명**한 것이어야 하며, 서명된 부분만 믿습니다.
- 이 브라우저가 시작한 로그인 요청에 대한 응답이어야 하고, NamiFAX 앞으로 온 것(대상과 수신처)이어야 하며, 유효 시간 안(2분의 시계 차이는 허용)이어야 하고, 이전에 쓰이지 않은 것이어야 합니다.
- 사용자는 **이메일 주소**로 찾습니다(`@` 앞부분으로는 찾지 않습니다). 그 주소의 계정이 없고 JIT가 켜져 있으면 계정을 만듭니다. 사용자 이름은 NameID의 `@` 앞부분에서 만들고(겹치면 숫자를 붙여 유일하게 만듭니다), *기본 권한*이 정하지 않는 한 관리자 권한은 없으며, 아무도 모르는 무작위 비밀번호가 설정됩니다.
- JIT가 꺼져 있고 일치하는 계정이 없으면 로그인 화면으로 돌아가 *ID 공급자가 알려 준 사용자와 일치하는 계정이 없습니다.*가 나옵니다.
- 비활성화된 계정은 비밀번호 로그인과 마찬가지로 거절됩니다.

SAML 로그인은 TOTP 코드를 묻지 않고 로그인 시도 제한에도 걸리지 않습니다.

### 인증 제공자에서 권한 가져오기

**권한을 ID 공급자(IdP)에서 가져오기**를 켜면 **로그인할 때마다** IdP가 계정의 권한을 정합니다. [사용자](users.md) 화면에서 손으로 바꾼 권한은 다음 SSO 로그인 때 덮어써지고, IdP가 더는 보내지 않는 역할의 권한은 회수됩니다.

| 항목 | 기본값 | 의미 |
|---|---|---|
| **역할이 들어 있는 속성** | `Role` | 사용자의 역할 목록을 담은 SAML 속성의 이름입니다. |
| **역할: 관리자** | `namifax-admin` | *관리자 콘솔* 권한을 주는 역할입니다. |
| **역할: 슈퍼유저** | `namifax-superuser` | *최고 관리자 권한*(콘솔 포함)을 주는 역할입니다. |
| **역할: 팩스 삭제 가능** | `namifax-can-delete` | *팩스 삭제 권한*을 줍니다. |
| **역할: 아무 회선으로 전송** | `namifax-any-modem` | *모든 모뎀 발신 권한*을 줍니다. |
| **회선이 들어 있는 속성** | 비어 있음 | 사용자가 쓸 **팩스 회선**의 장치 이름 목록을 담은 속성입니다. |
| **카테고리가 들어 있는 속성** | 비어 있음 | **카테고리** 이름 목록을 담은 속성입니다. |
| **DID 경로가 들어 있는 속성** | 비어 있음 | DID 라우트 코드나 별칭 목록을 담은 속성입니다. |

역할 칸을 비워 두면 그 권한은 부여되지 않습니다. 회선, 카테고리, DID 경로는 속성 이름을 비워 두면 *관리하지 않음*이어서 사용자 화면에서 정한 값이 그대로 남고, NamiFAX에 없는 이름은 무시됩니다.

## 패스키(WebAuthn)

- 사용자는 자기 설정(**FIDO2 패스키 및 생체 보안 키**의 **새 패스키 등록**)에서 패스키를 직접 등록하고 지울 수 있습니다. 다른 사용자의 패스키를 보거나 폐기하는 관리 화면은 없습니다.
- 패스키는 등록할 때 접속한 호스트 이름에 묶입니다(NamiFAX가 그 호스트 이름을 신뢰 당사자 ID로 씁니다). NamiFAX의 주소를 하나로 유지하십시오. 다른 호스트 이름으로 등록한 패스키는 새 주소에서 동작하지 않습니다. 브라우저는 HTTPS 페이지(와 `localhost`)에서만 패스키를 허용합니다.
- 패스키 로그인은 계정이 활성 상태인지만 확인합니다. TOTP 코드를 **묻지 않으며** 로그인 시도 제한에도 **걸리지 않습니다.** 현재 설계에서 의도한 동작입니다.

## TOTP(인증 앱)와 복구 코드

- TOTP는 선택 사항이며 **사용자별**입니다. 관리자가 모든 사용자에게 강제하는 스위치는 없습니다. 사용자가 자기 설정에서 켜며(앱의 코드로 확인하고 복구 코드를 받습니다), 끄려면 비밀번호와 올바른 코드가 필요하고 새 복구 코드를 만들려면 올바른 코드가 필요합니다.
- 사용자가 TOTP를 켰으면 **비밀번호** 로그인(로그인 화면을 거치는 시스템 비밀번호·웹 서버 로그인 포함) 다음에 코드 단계가 나옵니다. 패스키와 SAML 로그인은 이 단계를 건너뜁니다.
- 틀린 코드를 5번 입력하면 그 사용자는 15분 동안 코드 단계가 잠기며, 이때는 맞는 코드도 거절됩니다. 이 두 숫자는 프로그램에 고정되어 있으며 아래 제한 변수와 무관합니다.
- 사용자가 인증 앱과 복구 코드를 모두 잃었다면 서버에서 `namifax reset-2fa <사용자이름>`으로 그 사용자의 TOTP를 끕니다([사용자](users.md) 참고).

## 로그인 시도 제한 {#throttle}

로그인 양식에서 틀린 비밀번호를 세어 추측 공격을 막습니다. 카운터 두 개가 나란히 돕니다.

| | 계정(사용자 이름 기준) | 주소(클라이언트 IP 기준) |
|---|---|---|
| 한도 | `NAMIFAX_LOGIN_MAX_FAILURES`, 기본 **5** | 그 10배, 기본 **50** |
| 일어나는 일 | 계정이 **잠깁니다.** 비밀번호를 더는 보지 않으므로 맞는 비밀번호도 소용없습니다. | 주소가 `NAMIFAX_LOGIN_LOCK_MINUTES`분(기본 **15**) 동안 잠기고, 그 뒤 다시 시도할 수 있습니다. |
| 끝나는 때 | **저절로 끝나지 않습니다.** 관리자가 풀어야 합니다. | 시간이 지나면 끝납니다. |
| 세는 방식 | 마지막으로 로그인에 성공한 때부터 셉니다. 실패는 사라지지 않습니다. | 잠금 시간과 같은 길이의 구간 안에서 셉니다. |
| 메시지 | *로그인 실패가 너무 많아 이 계정이 잠겼습니다. 관리자가 잠금을 해제할 때까지 로그인할 수 없습니다.* | *로그인 실패가 너무 많습니다. 잠시 후 다시 시도하십시오.* |

알아 둘 점입니다.

- 실패는 계정이 **있든 없든** 사용자 이름별로 세므로, 응답만으로는 어떤 이름이 실제로 있는지 알 수 없습니다.
- 올바른 비밀번호를 입력하면 계정의 실패 횟수가 지워집니다. 이미 걸린 잠금은 로그인에 성공해도 풀리지 않습니다.
- 한 주소가 사무실 전체나 프록시일 수 있으므로 주소 한도가 더 높습니다.
- **계정 잠금을 풀려면** [사용자](users.md) 목록에서 **잠금 해제**를 누르거나 서버에서 `namifax unlock-user <사용자이름>`을 실행합니다. 주소 잠금은 시간이 다 되기 전에 풀 방법이 없습니다.
- 두 변수는 로그인이 일어날 때 읽습니다. 서비스 환경(예: `/etc/namifax.env`, [HylaFAX 설치](../../install/hylafax.md) 참고)에 적고 서비스를 다시 시작하십시오. 양의 정수가 아닌 값은 기본값으로 대체됩니다.
- 카운터는 데이터베이스에 저장되므로 모든 워커 프로세스가 공유하고, 재시작해도 지워지지 않습니다.

## 세션

- 로그인 쿠키 `namifax_session`은 `HttpOnly`, `SameSite=Lax`입니다. ini 파일에 `session.secure = true`를 쓰거나, ini 값이 없을 때 `NAMIFAX_SESSION_SECURE`가 `1`/`true`/`yes`이면 `Secure`가 붙습니다. NamiFAX를 HTTPS로 제공한다면 켜십시오.
- 로그인 세션은 웹 프로세스의 메모리에 있습니다. **2시간 동안 요청이 없으면** 끝나며(요청할 때마다 시간이 다시 시작되고, 설정으로 바꿀 수 없습니다), 웹 서비스를 다시 시작하면 모든 사람이 로그아웃됩니다.
- 두 번째 쿠키 `namifax_flow`에는 TOTP 단계, 비밀번호 변경 단계, SAML·패스키 챌린지 같은 짧은 흐름이 담깁니다. 30분 동안 유지되며 `NAMIFAX_SESSION_SECRET`(또는 `session.secret`)으로 서명합니다. **고정된 값을 지정하십시오.** 없으면 프로세스마다 무작위 비밀을 만들어, 재시작하거나 워커가 둘 이상일 때 이 단계들이 끊깁니다.
- 사용자 화면에서 바꾼 권한: *관리자 콘솔*과 *최고 관리자* 플래그는 다음 로그인부터, 팩스 회선·DID 경로·카테고리·삭제 권한은 바로 적용됩니다.
- 사용자 비밀번호는 Argon2id 해시로 저장됩니다. TOTP 시드, SMTP 비밀번호, S3 시크릿은 `NAMIFAX_SECRET_KEY`로 암호화해 저장하므로 이 키를 안전하게 보관하십시오. 키가 없으면 암호화된 값을 되살릴 수 없습니다.
- 로그인 화면의 *비밀번호를 잊으셨습니까?*는 계정의 이메일 주소로 새 무작위 비밀번호를 보내며([SMTP 게이트웨이](system.md) 사용), 사용자는 다음 로그인 때 새 비밀번호를 정해야 합니다.

[운영 점검표](../../install/operations-checklist.md)도 함께 보십시오.

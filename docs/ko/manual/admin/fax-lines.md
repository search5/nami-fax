# 팩스 회선과 라우팅

이 페이지는 팩스 회선을 기술하고 수신 팩스가 어디로 갈지 정하는 화면을 다룹니다. **팩스 모뎀 장치**, **DID 수신 라우팅**, **바코드 라우팅**, **팩스 카테고리 관리**, **팩스-이메일 라우팅**, **동적 차단 목록(DynConf)**입니다.

## 수신 팩스는 이렇게 라우팅됩니다

HylaFAX가 팩스를 받으면 `faxrcvd` 훅이 받은 팩스함에 올린 뒤 카테고리, 메일 연락처, 프린터를 정합니다. 단계는 아래 순서로 진행되며, 뒤 단계는 자기가 값을 가진 항목만 앞 단계의 값을 덮어씁니다.

1. **회선 또는 DID 경로.** DID 라우팅이 **꺼져** 있으면(`ENABLE_DID_ROUTING` 없음) 받은 회선의 설정([팩스 모뎀 장치](#modems)의 **연락처 이메일**, **프린터**, **카테고리**)을 씁니다. DID 라우팅이 **켜져** 있으면 걸려 온 DID 번호와 **라우트 코드**가 같은 경로의 설정을 쓰고, 회선 자체의 설정은 쓰지 않습니다.
2. **팩스-이메일.** 보낸 쪽 팩스 번호가 주소록에 있고 그 번호에 **이메일**, **프린터**, **카테고리**가 있으면 위의 값을 대신합니다.
3. **바코드.** 바코드 지원이 켜져 있고 팩스에서 바코드를 읽었다면, 일치하는 **바코드 라우팅** 규칙이 가진 카테고리, 프린터, 연락처가 앞의 값을 대신합니다.

메일은 [SMTP 게이트웨이](system.md)를 거쳐 나갑니다. 프린터 출력은 훅이 `PRINTFAXRCVD`를 켠 상태로 돌 때만 일어납니다.

## 팩스 모뎀 장치 {#modems}

**팩스 모뎀 장치**(`/admin/modems`, 사이드바 *하드웨어 및 회선*)의 **활성 모뎀 회선**에는 NamiFAX가 아는 팩스 회선이 **장치**, **별칭**, **연락처**, **상태**와 함께 나옵니다.

!!! note
    여기에 입력하는 장치는 HylaFAX 서버에 실제로 있는 장치(시리얼 포트, USB 모뎀, 가상 IAX 모뎀)여야 합니다. 이 화면은 기록만 합니다.

### 추가, 수정, 삭제

오른쪽 양식을 씁니다(새 회선은 **모뎀 장치 설정**, 기존 회선은 **모뎀 편집 (…)**). 장치 이름을 누르면 수정 양식이 열립니다.

| 항목 | 의미 |
|---|---|
| **장치** \* | HylaFAX 장치 이름입니다. 예: `ttyS0`. |
| **별칭** \* | 알아보기 쉬운 이름입니다. 예: `Main Inbound Line`. |
| **연락처 이메일** | 이 회선으로 받은 팩스를 메일로 보낼 주소입니다(DID 라우팅이 꺼져 있을 때). |
| **프린터** | 이 회선으로 받은 팩스를 출력할 때 인쇄 명령에 넘기는 프린터 이름입니다(DID 라우팅이 꺼져 있을 때). 예: `lp0`. 그냥 글자로 입력합니다. |
| **카테고리** | 이 회선으로 받은 팩스에 붙일 카테고리입니다(DID 라우팅이 꺼져 있을 때). [팩스 카테고리](#categories)에서 고릅니다. |

- **만들기**로 회선을 추가합니다. 메시지는 *모뎀을 만들었습니다*, *장치 이름을 입력하세요*, *별칭을 입력하세요*, *이미 있는 모뎀입니다*입니다.
- **저장**은 별칭, 연락처, 프린터, 카테고리를 바꿉니다. 기존 회선의 장치 이름은 바꿀 수 없습니다. 저장할 때 장치 칸은 무시되므로, 이름을 바꾸려면 회선을 삭제하고 다시 만드십시오.
- **삭제**(확인 창이 뜹니다)는 NamiFAX에서 그 회선을 지웁니다.

### 상태

상태 문구는 페이지를 만들 때마다 웹 서버에서 HylaFAX `faxstat` 명령을 실행해 얻습니다. 나올 수 있는 값은 다음과 같습니다.

| 표시되는 상태 | 의미 |
|---|---|
| Running and idle | 모뎀이 비어 있습니다. |
| Sending fax {JID: n} | 작업 `n`을 보내는 중입니다. |
| Receiving from … / Receiving facsimile | 팩스를 받는 중입니다. |
| Please wait | `faxstat`이 이 장치에 대한 답을 주지 않았거나 위 상태가 아닙니다. |

대시보드도 각 회선 옆에 같은 상태를 보여 줍니다. 상태 문구는 번역되지 않고 영어로 나옵니다.

## DID 수신 라우팅 {#did}

`ENABLE_DID_ROUTING`이 켜져 있을 때만 쓸 수 있습니다. **DID 수신 라우팅**(`/admin/did`, `/admin/routing/did`도 같은 화면)의 **활성 DID 라우팅 규칙**에 **라우트 코드**, **별칭**, **연락처**, **프린터**가 나옵니다.

| 항목 | 의미 |
|---|---|
| **라우트 코드** \* | HylaFAX가 통화에 대해 알려 주는 DID 번호(내선)입니다. 정확히 같아야 일치합니다. |
| **별칭** \* | 알아보기 쉬운 이름입니다. |
| **연락처 이메일** | 이 경로로 온 팩스를 메일로 보낼 주소입니다. |
| **프린터** | 이 경로로 받은 팩스를 출력할 프린터 이름입니다. |
| **카테고리** | 이 경로의 팩스에 붙일 카테고리입니다(붙이지 않으려면 **-- 없음 --**). |

**새 DID 라우트**(또는 **초기화**)를 누르면 빈 양식이 열리고, 규칙의 **편집**을 누르면 그 규칙을 고칠 수 있습니다. 규칙을 연 상태에서는 **저장**, **삭제**(확인 창이 뜹니다), **취소**를 쓸 수 있습니다.

규칙이 없는 DID 번호로 팩스가 오면, `AUTOCONFDID`를 끄지 않은 한(기본은 켜짐) 훅이 그 번호를 라우트 코드와 별칭으로 하는 규칙을 스스로 만듭니다. 어떤 사용자가 이 경로의 팩스를 볼 수 있는지는 [사용자](users.md) 화면의 **DID 라우팅**에서 정합니다.

## 바코드 라우팅

`ENABLE_BARDECODE_SUPPORT`가 켜져 있을 때만 쓸 수 있습니다. **바코드 라우팅**(`/admin/barcodes`)은 팩스에서 읽은 바코드(화면 설명에 따르면 Code39 또는 QR)로 팩스를 라우팅합니다. 인식한 값은 팩스의 메모로도 저장됩니다.

항목은 **바코드** \*, **별칭** \*, **연락처 이메일**, **프린터**, **카테고리**입니다. 새 규칙은 **새 바코드 라우트**로 만들고, 규칙의 **편집**을 눌러 **저장**, **삭제**, **취소**를 합니다. 규칙의 **바코드**가 인식한 값과 같을 때 일치합니다.

## 팩스 카테고리 관리 {#categories}

**팩스 카테고리 관리**(`/admin/categories`)는 팩스를 분류하는 이름표를 관리합니다. **등록된 카테고리** 목록에 이름과 ID가 나옵니다.

- **새 카테고리**를 누르고 **카테고리명** \*(예: `Invoices`)을 입력한 뒤 **저장**합니다.
- 카테고리의 **편집**을 눌러 이름을 바꾸거나(**저장**) **삭제**(확인 창이 뜹니다)합니다. 카테고리를 삭제하면 그 카테고리가 붙어 있던 팩스에서도 카테고리가 제거됩니다.

카테고리는 사용자에게 카테고리 접근 권한을 줄 때([사용자](users.md)), 그리고 회선, DID 경로, 바코드 규칙, 팩스-이메일 번호의 **카테고리**로 쓰입니다. 이름을 비우면 거절됩니다(*Category Name is required*).

## 팩스-이메일 라우팅

**팩스-이메일 라우팅**(`/admin/fax2email`)은 특정 보낸 쪽에서 **온** 팩스를 어디로 보낼지 정합니다. **회사별 전달 규칙** 목록에는 주소록의 회사마다 팩스 번호 수와 이메일, 프린터가 나옵니다. 회사와 팩스 번호는 주소록에서 만들며(**주소록에서 회사 추가하기** 링크), 모르는 번호에서 팩스가 오면 수신 훅이 그 번호를 주소록에 스스로 추가합니다.

회사의 **편집**을 누르면 양식에 **회사** 이름과, 그 회사의 팩스 번호마다 번호(읽기 전용)와 다음 항목이 나옵니다.

| 항목 | 의미 |
|---|---|
| **이메일** | 주소 하나 이상이며 `,` 또는 `;`로 구분합니다. 모든 주소가 올바라야 합니다(*올바른 이메일 주소를 입력하십시오.*). |
| **프린터** | 프린터 이름입니다. |
| **카테고리** | 이 번호에서 온 팩스에 붙일 카테고리입니다. |

**저장**은 회사 이름(필수)과 번호마다 세 값을 저장합니다(*팩스 이메일 전달 설정을 저장했습니다*). **삭제**(확인 창이 뜹니다)는 회사와 *그 회사의 모든 팩스 번호*를 지웁니다. `ARCHIVEFAX2EMAIL`을 끄지 않은 한(기본은 켜짐), 이 규칙으로 전달한 팩스는 메일을 보내거나 출력한 뒤 보관함으로 옮겨집니다.

## 동적 차단 목록(DynConf) {#dynconf}

**동적 구성(DynConf)**(`/admin/dynconf`)은 발신자 번호로 수신 전화를 차단합니다. **차단된 발신자 번호** 목록에 규칙마다 발신자 번호, 장치(또는 *모든 장치*), ID가 나옵니다.

| 항목 | 의미 |
|---|---|
| **발신자 번호** \* | 상대방 번호입니다. 정확히 같아야 일치합니다(번호와 함께 오는 SIP의 `@호스트` 부분은 무시합니다). 입력 칸의 예시와 달리 패턴은 지원하지 않습니다. |
| **모뎀 장치** | 등록한 회선 중 하나, 또는 **모든 장치**입니다. |

**새 규칙**을 누르고 **저장**하며, 규칙의 **편집**에서 **저장**, **삭제**, **취소**를 합니다. 이미 있는 규칙을 만들면 거절됩니다(*Rule already exists*).

규칙은 `dynconf` 훅이 HylaFAX에 연결되어 있어야([HylaFAX 설치](../../install/hylafax.md)) 효과가 있습니다. 전화가 올 때마다 HylaFAX가 훅에 묻고, 훅은 차단 대상이면 `RejectCall: true`로 답합니다. 규칙은 다음 통화부터 적용되며, 확인할 때마다 [시스템 로그](system.md)에 기록이 남습니다.

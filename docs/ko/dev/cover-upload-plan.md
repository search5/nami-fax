# 팩스 표지 업로드 계획

관리자 화면 `/admin/covers`에서 표지 파일을 올리고, 이미 올라간 파일을 찾아보아 고를 수 있게 하는 작업의 계획입니다.
이 문서는 계획이며, 아직 구현된 것은 없습니다. 아래 "확인된 현재 상태"는 2026-10-03에 코드와 원본(`git show 9408385:legacy/avantfax/...`)을 읽어 확인한 내용입니다.

## 1. 배경

신규 기능 계획서(`llm-wiki/sources/new-features-plan.md` §3.5)는 표지 스튜디오에서 "드래그앤드롭 업로드, 실시간 썸네일 미리보기, 동적 치환 변수 안내, PostScript·HTML·PDF 지원"을 약속했습니다.
그러나 현재는 서비스 코드만 있고 화면에 연결되어 있지 않습니다. 위키 `known-gaps-and-decisions.md` §3의 "표지 스튜디오" 줄이 이 상태를 "코드 존재"로만 적어 구현이 끝난 것처럼 읽히는 점도 함께 바로잡습니다.

## 2. 확인된 현재 상태

| 항목 | 원본 AvantFAX 3.x | 현재 NamiFAX |
| --- | --- | --- |
| 파일 업로드 | 없음. 서버에서 직접 복사 | 화면에 없음 |
| 화면 입력 | 제목, 파일 이름(글자 입력), 숨은 필드 `cover_id`, `_submit_check` | 같음 |
| 파일 존재 확인 | 하지 않음 | 하지 않음 |
| 중복 등록 | 같은 파일 이름이면 "Cover page already exists"로 거절 | 같음(`Covers.create`) |
| 저장 후 편집 | 제목만 바뀜(파일 이름은 바뀌지 않음) | 파일 이름도 바뀜(차이) |
| 발송 시 읽는 위치 | `$INSTALLDIR/images/<파일>` | `AVANTFAX_INSTALLDIR/images/<파일>`(`views/sendfax.py`, `services/sendfax_command.py`) |
| 서비스 `CoverStudioService` | 없음 | `.ps`, `.pdf`, `.html`, `.jinja2`를 받아 저장하고 등록. **호출하는 곳이 없음** |
| 서비스 저장 위치 기본값 | 해당 없음 | `/var/spool/hylafax/covers`(**발송이 읽는 위치와 다름**) |
| 표지 생성기가 쓰는 형식 | 해당 없음 | `.ps`, `.html`/`.htm`(`.html`은 `USE_HTML_COVERPAGE`가 켜져 있어야 함) |
| 업로드 크기 한도 | 해당 없음 | 표지에는 없음(첨부용 `NAMIFAX_MAX_UPLOAD_BYTES`와 `services/upload_check.py`가 있음) |

이 때문에 `CoverStudioService`를 지금 모습 그대로 연결하면 두 가지 문제가 생깁니다.
1. 올린 표지가 목록에는 보이지만 발송할 때 파일을 찾지 못합니다(저장 위치가 다름).
2. `.pdf`와 `.jinja2`는 올릴 수 있지만 표지 생성기가 쓰지 못합니다.

## 3. 목표와 범위

목표
1. 새 표지 추가 모드와 편집 모드에서 표지 파일을 올릴 수 있습니다.
2. 이미 올라간 표지 파일을 목록에서 찾아보아 고를 수 있습니다.
3. 올린 표지가 발송에서 실제로 사용됩니다.
4. 원본의 폼 계약과 동작(제목과 파일 이름 필수, 중복 등록 거절)을 깨뜨리지 않습니다.

범위 밖(별도 작업)
- 썸네일 미리보기: `.ps` 변환 방법(Ghostscript 등)을 정해야 하므로 별도로 다룹니다.
- `.pdf`와 `.jinja2` 표지: 표지 생성기에 해당 형식 지원이 없으므로 이 작업에서 제외합니다.
- 표지 파일 삭제: 등록 해제와 파일 삭제는 다른 동작이므로 이 작업에서는 등록 해제만 유지합니다.

## 4. 결정 사항

사용자가 확정해야 하는 항목입니다. 확정 전까지는 권장안으로 계획합니다.

| # | 질문 | 권장안 | 상태 |
| --- | --- | --- | --- |
| D1 | 같은 이름의 파일이 이미 있을 때 | 기본은 거절하고, "덮어쓰기"를 체크한 경우에만 허용합니다. 같은 파일을 쓰는 다른 표지의 발송 결과가 바뀌기 때문입니다 | [NEEDS_CLARIFICATION: 거절만 할지, 덮어쓰기 체크를 둘지] |
| D2 | 업로드 허용 형식 | `.ps`, `.html`(`.htm` 포함). 생성기가 쓰는 형식과 같게 합니다 | [NEEDS_CLARIFICATION: 두 형식으로 줄이는 데 동의하는지] |
| D3 | 편집 화면에서 파일 이름 변경 | 원본처럼 제목만 바뀌게 하고, 파일은 찾아보기나 업로드로 고르는 별도 동작으로 둡니다. 현재의 파일 이름 변경 동작은 유지 여부를 정해야 합니다 | [NEEDS_CLARIFICATION: 파일 이름 변경을 유지할지] |

D3은 원본과의 차이이므로 결정 전에는 현재 동작(파일 이름도 바뀜)을 유지하고, 결정되면 시험과 함께 바꿉니다.

## 5. 설계

### 5.1 폼 계약

원본의 입력 `title`, `file`, `cover_id`, `_submit_check`와 버튼 `create`, `save`, `delete`는 그대로 둡니다.
추가하는 요소는 모두 선택 기능입니다.
- 파일 선택 입력 `cover_upload`(`enctype="multipart/form-data"`). 올리면 `file` 칸이 올린 파일 이름으로 채워집니다.
- 덮어쓰기 체크 `overwrite`(D1 결정에 따름).
- 찾아보기 목록. 항목을 고르면 `file` 칸에 이름이 채워집니다(스크립트가 없어도 `file` 칸에 직접 입력할 수 있음).
- 폼 토큰 `csrf_token`.

기존 요청 형식(`title`과 `file`만 보내는 요청)은 그대로 동작해야 합니다.

### 5.2 저장 위치와 서비스

- 저장 위치는 발송이 읽는 `AVANTFAX_INSTALLDIR/images`로 통일합니다. `CoverStudioService`의 기본값 `/var/spool/hylafax/covers`는 이 값으로 바꾸고, 환경 변수 `AVANTFAX_COVERS_DIR`는 쓰지 않거나 같은 폴더를 가리키게 정리합니다.
- 서비스 `save_template`는 형식 검사 후 저장하고 등록하는 흐름을 유지하되, 다음을 더합니다.
  - 파일 이름 검사: 경로 구분자 금지(`os.path.basename`과 별도로, 이름이 바뀌면 거절), 숨김 파일 금지, 허용 문자 제한
  - 크기 상한: 표지 전용 설정(기본값은 첨부 한도보다 작게)
  - 내용 확인: `.ps`는 `%!PS`로 시작하는지, `.html`은 텍스트인지
  - 같은 이름 처리(D1)
  - 같은 파일 이름이 이미 `CoverPages`에 등록되어 있으면 원본처럼 "Cover page already exists"로 거절
- 쓰기 실패(폴더 권한 없음)는 오류 화면으로 알립니다. 배포 문서에 `images` 폴더가 웹 서버 사용자에게 쓰기 가능해야 한다는 점을 적습니다.

### 5.3 찾아보기

- 같은 폴더에서 허용 형식의 파일만 이름 순으로 나열합니다. 경로는 받지 않고 파일 이름만 다룹니다.
- 각 파일 옆에 사용 중인 표지(제목)를 표시하고, 등록되지 않은 파일은 "등록 안 됨"으로 표시합니다.
- 다른 폴더나 상위 경로는 볼 수 없습니다.

### 5.4 화면

- 새 표지 추가와 편집 모드 모두 업로드와 찾아보기를 보여 줍니다.
- Tailwind 유틸리티로 기존 화면의 톤을 따르고, 드래그앤드롭은 스크립트가 있을 때만 동작하게 합니다(스크립트가 없어도 파일 선택으로 올릴 수 있음).
- 새 문구는 한국어 카탈로그 `ko/namifax.po`에 함께 추가합니다. 다른 언어 카탈로그는 이번 작업에서 건드리지 않습니다(전체 갱신 시 대량 변경이 생기므로).

## 6. 구현 순서

한 단계에서 시험을 먼저 쓰고, 통과를 확인한 뒤 다음 단계로 갑니다.

1. 서비스: 저장 위치 통일, 파일 이름 검사, 크기 상한, 내용 확인, 중복 처리
2. 뷰: `/admin/covers`에 업로드 처리를 연결(`cover_upload`, 폼 토큰, 권한)
3. 찾아보기 목록과 화면 폼
4. 발송 연결 확인: 올린 표지로 실제 발송 계획이 만들어지는지 시험
5. 문서: 배포 문서의 폴더 권한 설명, 위키 갱신

## 7. 시험 계획

서비스
- 허용 형식이 저장되고 `CoverPages`에 등록된다
- 허용하지 않는 확장자, 내용이 형식과 다른 파일, 크기 초과가 거절된다
- 경로가 섞인 이름(`../x.ps`, `a/b.ps`, `.hidden.ps`)이 거절된다
- 같은 이름: 기본 거절, 덮어쓰기를 켜면 허용(D1)
- 이미 등록된 파일 이름은 원본 문구로 거절된다

뷰
- 새 표지와 편집 모드 모두에서 업로드가 되고 `file` 칸이 채워진다
- 폼 토큰이 없으면 거절된다
- 관리자가 아닌 사용자는 올릴 수 없다
- `title`과 `file`만 보내는 기존 방식이 그대로 동작한다
- 찾아보기 목록에 허용 형식 파일만 나오고, 폴더 밖 파일은 나오지 않는다

발송 연결
- 올린 표지의 이름이 발송 화면 목록에 나오고, 발송 계획의 표지 경로가 올린 파일을 가리킨다

서버 DB 시험: 이 기능은 DB를 새로 쓰지 않으므로 SQLite 시험이면 충분하다고 봅니다. 다만 `CoverPages` 등록은 기존 쿼리를 쓰므로 전체 시험을 4개 DB에서 한 번 돌려 확인합니다.

## 8. 완료 기준

- 위 시험이 모두 통과하고, 전체 시험(SQLite)에서 새 실패가 없습니다.
- 업로드한 표지가 발송 화면에 나타나고 발송 계획에 반영됩니다.
- 위키(`known-gaps-and-decisions.md`, `new-features-plan` 관련 서술, `log.md`)가 실제 상태로 갱신됩니다. PDF, Jinja2, 썸네일은 "미구현"으로 적습니다.

## 9. 위험과 대응

| 위험 | 대응 |
| --- | --- |
| `images` 폴더가 웹 서버 사용자에게 쓰기 불가 | 쓰기 실패를 화면 오류로 알리고 배포 문서에 권한을 적는다 |
| 같은 이름 덮어쓰기로 다른 표지의 결과가 바뀜 | 기본 거절(D1), 덮어쓸 때 사용 중인 표지 목록을 경고로 보여 준다 |
| 올린 HTML 안의 스크립트 | 표지는 서버에서 변환될 뿐 화면에 직접 렌더링하지 않으므로 화면 위험은 낮지만, 변환 도구가 외부 자원을 읽는지 구현 전에 확인한다 |
| `USE_HTML_COVERPAGE`가 꺼져 있으면 `.html`이 쓰이지 않음 | 업로드 화면에 설정 상태를 안내하고, 꺼져 있을 때의 동작을 시험으로 고정한다 |
| 원본과 다른 파일 이름 변경 동작 | D3 결정 후 처리하고, 결정 전에는 현재 동작을 유지한다 |

## 10. 확인하지 못한 것

- HTML 표지 변환 도구(`html2ps`)가 외부 자원을 읽는 방식은 확인하지 않았습니다.
- 실제 HylaFAX `faxcover`와 연결한 발송은 현재 환경에서 시험하지 못하므로, 발송 연결은 발송 계획(명령 구성) 수준까지만 확인합니다.
- 실제 배포 환경의 `images` 폴더 소유자와 권한은 확인하지 않았습니다.
